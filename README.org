* readability-metric

Readability metrics for EPUB books.

** Nix usage

Process a directory of EPUB files to JSON Lines:

#+begin_src shell
nix run . -- --corpus-dir ~/Downloads --output results/downloads-readability.jsonl --jobs 4
#+end_src

Run the test suite:

#+begin_src shell
nix develop -c make test
#+end_src

Build the packaged command:

#+begin_src shell
nix build
#+end_src

** Python usage

#+begin_src shell
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m readability_metric --corpus-dir ~/Downloads --output results/downloads-readability.jsonl
#+end_src

** Output

The default batch processor writes one JSON object per line. Each record includes EPUB metadata, detected language, token counts, vocabulary-growth fit parameters when the book is below the configured size limit, and per-file errors without stopping the whole batch.

For ranking by lexical difficulty, prefer =predicted_unique_words_20k= over the raw slope. It estimates how many unique word forms the model expects in the first 20,000 words, using both the fit slope and intercept. Lower values mean slower vocabulary growth and therefore easier books by this metric. The output also includes =lexical_ease_percentile_by_language=, where 100 is easiest within the same detected language.

#+begin_src shell
jq -r '
  select(.language=="ca" and .status=="ok" and .predicted_unique_words_20k != null)
  | [.lexical_ease_percentile_by_language, .predicted_unique_words_20k, .word_count, .unique_words, (.creator // ""), (.title // "")]
  | @tsv
' results/downloads-readability.jsonl | sort -nr | head -20
#+end_src

The legacy MongoDB path is still available by passing =--database= with =--book= or =--corpus-dir=.

** Chinese Story Ladder Pipeline

Generate a staged set of beginner-level Chinese stories from an EPUB corpus:

#+begin_src shell
python3 story_pipeline.py \
  --corpus-dir ~/haodoo \
  --output-dir ~/haodoo-stories \
  --stages 12 \
  --stage-word-count 8 \
  --min-repetitions 5 \
  --target-ratio 0.98
#+end_src

The output bundle contains:

- `curriculum.json`: ordered stage manifest and quality metrics
- `stage_XX.html`: hidden-text HTML book file with reveal control and audio reference
- `stage_XX.txt`: plain text copy
- `stage_XX.json`: per-stage metadata (coverage, repeats, unknown streak)
- `stage_XX.tts.json`: shell command suggested for text-to-speech

Important defaults are exposed via CLI:

- target known-word coverage before introducing new words (`--target-ratio`, default `0.98`)
- minimum repetitions per new word per stage (`--min-repetitions`, default `5`)
- number of new words per stage (`--stage-word-count`, default `8`)
- max generated sentences per stage (`--max-sentence-count`, default `30`)

`StoryDraft` includes both:
- `known_ratio`: coverage against previously known words
- `known_ratio_with_introduced`: coverage after adding that stage’s new words

This is a practical starter toward a zero-cognate path: you can use the generated HTML for listening-first reading by creating audio with the emitted TTS command, then un-hiding text gradually.
